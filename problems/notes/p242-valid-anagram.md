# 242. 有效的字母异位词

- 难度 / 类型：简单 · 哈希 / 计数
- 思路（一句话）：长度不同直接 `false`；长度相同就用一个计数数组，s 的字符 +1、t 的字符 -1，最后看是否全为 0。
- 复杂度：时间 O(n)，空间 O(1)（`[26]int` 是定长数组；字符集超出 a-z 的兜底分支是 O(k)，k 为不同字符数）
- 卡点：
  1. **快路径的前置判断必须同时检查 s 和 t**。只查 `s` 时，如果 `t` 里出现 `'A'` 之类字符，`cnt[t[i]-'a']` 会算出负下标 —— 运行期 panic。这是本题最容易漏的一处（测试里用 `"abc"` / `"abC"` 专门抓它）。
  2. 不能用「字符求和相等」判断异位词：`ad` 与 `bc` 和相同，但不是异位词；「字符乘积相等」同样不行（`ab` 与 `cc`）。
  3. 长度比较用 `len(s) != len(t)`（按字节）就够：异位词的多重集相同，编码后的字节数必然相同。注意它只是必要条件，作用只是快速否决。
  4. 「一边 +1 一边 -1」比「分别统计两个数组再逐个比」少一遍循环，也不容易漏字符。
- Go 注意点：
  - **为什么 `[26]int` 比 `map[byte]int` 快**：定长数组在栈上分配（是否逃逸留到 W43 之后再看），寻址就是「基址 + 下标」一条指令；map 每次读写都要算哈希、定位桶、比较 key，还可能触发扩容，并多一层指针间接寻址和内存分配。字符集已知且很小的时候，数组计数是常数级最优解 —— 这就是「key 空间小用数组，key 空间大才用 map」。
  - 若字符集超出 a-z（大写、数字、中文），26 个格子装不下，应改用 `map[rune]int`。key 必须用 **rune**：汉字在 UTF-8 里是多字节，用 byte 计数会把它拆成 3 个「字符」（本实现自带这个兜底分支，所以 `"中文"` / `"文中"` 也能判对）。
  - `range string` 得到的是 `(字节下标, rune)`；想要「第几个字符」需要 `[]rune` 或自增计数器。
- 关键代码片段：

```go
if isLowerAlphaASCII(s) && isLowerAlphaASCII(t) {
	var cnt [26]int
	for i := 0; i < len(s); i++ {
		cnt[s[i]-'a']++ // s 的字符 +1
		cnt[t[i]-'a']-- // t 的字符 -1
	}
	// 之后只需检查 cnt 是否全 0
}
```
