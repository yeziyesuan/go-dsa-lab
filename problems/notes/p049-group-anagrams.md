# 49. 字母异位词分组

- 难度 / 类型：中等 · 哈希 / 计数指纹
- 思路（一句话）：把「字符计数指纹」当 map 的 key，指纹相同的串就是一组。
- 复杂度：时间 O(N·L)（N 个串、平均长 L；走 rune 排序兜底分支时 O(N·L log L)），空间 O(N·L)
- 卡点：
  1. **返回值顺序不定**：分组先后取决于输入顺序，Go 的 map 遍历顺序又是随机的。测试不能直接比 `[][]string`，必须「组内排序 + 整体按首元素排序」后再比（见测试里的 `normalizeGroups`）。这是本题唯一真正恶心的地方。
  2. 计数数组转字符串当 key 时，每个计数只占 1 字节，最大 255。LeetCode 约束单串长 ≤ 100，安全；串长若可能超过 255，同字母计数会回绕串味，必须换成变长编码（如 `strconv.Itoa`）。
  3. 不能用「字符求和」「字符乘积」当 key：`ad`/`bc` 和相同，`ab`/`cc` 积相同，会把不该同组的混在一起（测试里有 `["ad","bc","da"]` 用例）。
  4. `res[i] = append(res[i], s)` 一定要把结果写回 `res[i]`：`append` 可能换底层数组，丢掉返回值新元素就没了。
  5. 空串 `""` 的 key 是 26 个 0，天然和别的空串一组，且与 `"a"` 的 key 不同，不会混组。
- Go 注意点：
  - **map 的 key 必须可比较**：`string` 可以，`[]byte` / `[]rune` 不行 —— 这就是要把计数数组「转成」字符串的原因。`[]byte` → `string` 的转换会拷贝一份内容，得到的 `string` 才是合法且不可变的 map key。
  - `[26]byte` 本身是数组（值类型、可比较），也能直接当 key，但用 `string` 更通用（能兼容 rune 排序分支）。
  - 计数分支用 `[26]byte` 而不是 `[26]int`，是为了 `string(cnt[:])` 时每个字母正好占 1 字节；用 `int` 的话每个计数占 8 字节，key 会长得多。
- 关键代码片段：

```go
k := anagramKey(s)
if i, ok := idx[k]; ok {
	res[i] = append(res[i], s)
	continue
}
idx[k] = len(res)
res = append(res, []string{s})
```
