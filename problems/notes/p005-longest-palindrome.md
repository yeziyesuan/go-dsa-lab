# 5. 最长回文子串

- 难度 / 类型：中等 · 中心扩展 / 字符串
- 思路（一句话）：枚举 2n-1 个「中心」（单字符中心 + 双字符间隙中心），从中心向两边扩到扩不动为止，取最长的那一段。
- 复杂度：中心扩展法时间 O(n²)、空间 O(n)（`[]rune` 拷贝）；暴力法时间 O(n³)、空间 O(n)
- 卡点：
  1. 中心有 **2n-1** 个。只枚举「单个字符」中心会漏掉全部偶数长度回文（`"bb"`、`"abba"`）。
  2. 扩展循环退出时两侧已经不相等了，真正的回文区间是 `[lo+1, hi-1]`；直接用 `[lo, hi]` 会多带一个不匹配的字符 —— 中心扩展法最常写错的一行。
  3. 相等长度时取舍要固定（用 `>` 比较，保留先出现的那个），否则「多解」用例（`"babad"` 可以是 `"bab"` 也可以是 `"aba"`）会让测试结果飘。
  4. 测试要用「可接受答案集合」比较，不能直接比字符串。
  5. 多字节字符必须按 rune 处理：照搬 `s[i]` 的字节下标写法时，`"中文"` 的「最长回文」会退化成一个孤立的 `0xE4` 字节（非法 UTF-8），因为单个字节永远等于自己。
- Go 注意点：
  - 先 `[]rune(s)` 再操作：`rune` 是 `int32` 码点，切片下标就是「第几个字符」，多字节安全；代价是一次 O(n) 拷贝，而且不能再用字节下标切原串，要用 `string(rs[lo:hi+1])` 还原。
  - 对照：纯 byte 版零拷贝、ASCII 下更快，但遇到 UTF-8 多字节字符会把字符切碎，所以通用实现选 rune 版。
  - 文件里另写了不导出的 `longestPalindromeBrute`（暴力对照）：暴力法是「枚举区间 + 验证回文」，中心扩展法是「枚举中心 + 生长」；前者把 O(n) 的验证重复做了 O(n²) 次，后者把验证融进生长过程，于是省掉一个 n。测试用暴力解交叉验证中心扩展法的长度。
  - 不导出的辅助函数（`expandRunes`、`longestPalindromeBrute`）在 Go 里「定义了没被非测试代码调用」不会报错（未使用的报错只针对局部变量和 import），但仍要小心 `go vet` 之外的可读性。
- 关键代码片段：

```go
for i := range rs {
	if lo, hi := expandRunes(rs, i, i); hi-lo > bestHi-bestLo {
		bestLo, bestHi = lo, hi // 奇数长度中心
	}
	if lo, hi := expandRunes(rs, i, i+1); hi-lo > bestHi-bestLo {
		bestLo, bestHi = lo, hi // 偶数长度中心
	}
}
```
