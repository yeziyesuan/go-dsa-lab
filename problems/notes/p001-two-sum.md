# 1. 两数之和

- 难度 / 类型：简单 · 哈希
- 思路（一句话）：一遍遍历，边走边把「值 -> 下标」存进 map，遇到 `target-v` 已经在表里就直接返回那一对下标。
- 复杂度：时间 O(n)，空间 O(n)
- 卡点：最容易写成「先把整个数组塞进 map 再遍历查找」——遇到重复值会把旧下标覆盖掉，`nums=[3,3], target=6` 就变成自己配自己。正确顺序是**先查、后存**，一遍走完。第二个坑是 `target-v` 写成 `v-target`，负数用例直接全挂。
- Go 注意点：`j, ok := seen[target-v]` 的二值取法是本题核心，不能写成 `j := seen[...]; if j != 0`——下标 0 是合法答案，而 map 未命中时返回的零值也是 0。另外 `make(map[int]int, len(nums))` 带上容量能少几次扩容。
- 关键代码片段：

```go
for i, v := range nums {
	if j, ok := seen[target-v]; ok {
		return []int{j, i}
	}
	seen[v] = i
}
```

## 我的卡点（2026/9/22，第一遍自己写的时候）

- **做法**：暴力双重循环，`j := i + 1` 保证同一个下标不用两遍 → **时间 O(n²) / 空间 O(1)**；三组示例实跑通过（`[2,7,11,15],9 → [0 1]`、`[3,2,4],6 → [1 2]`、`[3,3],6 → [0 1]`）。练习代码在 `playground/p001_two_sum/main.go`。
- **卡点①（编译器层面）**：以为"题目保证一定有解、循环里必定 return"，就**没写函数末尾的兜底 return** → `go build` 直接报 `missing return`。
  教训：**Go 只认控制流，不认业务保证** —— 两层 `for` 之后必然还有一条"一对都没找到"的出口，循环外面必须补 `return nil`。
- **卡点②（方法层面）**：写完只跑了题目给的 3 组示例就以为过了。示例全是"有解 + 正数 + 小数组"，真正要看的是**边界**（nil / 空 / 单元素 / 无解 / 重复 / 答案在末尾）和**最坏耗时**（n = 10⁴ 时约 5×10⁷ 次比较）。
- **还没做**：上面「思路」写的哈希版 O(n) —— 按计划「看了解法隔天重做」的规矩，**9/23 不看答案自己写一遍**。
