## 一、必看（W1 只挑这 4 个）

| 优先级 | 资料 | 用途 | 本周花多久 |
|---|---|---|---|
| ★★★ | **A Tour of Go** <https://go.dev/tour/>（右上角可切中文；社区中文版 <https://tour.go-zh.org/>） | 语法主线：变量→流程→切片→map→方法→接口→并发。**边看边在 `syntax/` 里重敲** | 3–4 小时，分 4 天 |
| ★★★ | **Go by Example** <https://gobyexample.com/>（中文翻译 <https://books.studygolang.com/gobyexample/>） | 每个语法点一段最小可运行代码，比 Tour 更适合「照着敲」 | 2 小时，随查随用 |
| ★★★ | **Go Blog: Arrays, slices (and strings): The mechanics of 'append'** <https://go.dev/blog/slices> | **切片共享底层数组**这个头号坑的唯一权威解释，配 `syntax/03_slice` 一起看 | 40 分钟，看两遍 |
| ★★★ | **标准库文档** <https://pkg.go.dev/std> | 周六**上机块**（08:00–15:30）里查 `strings` / `strconv` / `sort` / `fmt` 的函数签名。**只查不读** | 周六上机块 |

## 二、查语义细节时用

| 优先级 | 资料 | 用途 |
|---|---|---|
| ★★ | **Effective Go** <https://go.dev/doc/effective_go> | 「Go 为什么这么写」的官方解释：错误处理、接口、并发风格 |
| ★★ | **Go 语言规范** <https://go.dev/ref/spec> | 查精确语义（如 `append` 返回值、int 位宽、`for range` 的变量语义）。**别通读**，当字典用 |
| ★★ | **Go Code Review Comments** <https://go.dev/wiki/CodeReviewComments> | 命名、错误消息、注释惯例。想写出「像 Go 的代码」就看它 |
| ★ | **Go 官方 Blog 列表** <https://go.dev/blog/> | W2 的并发、W4 之后的切片/性能文章都在这 |

## 四、环境与工具

| 项 | 命令 / 位置 |
|---|---|
| 国内模块代理（**必设**） | `go env -w GOPROXY=https://goproxy.cn,direct` ｜ <https://goproxy.cn> |
| Go 下载页（winget 失败时用） | <https://go.dev/dl/>（`.msi` 双击装，或 `.zip` 解压后把 `go\bin` 加进 PATH） |
| VS Code + Go 扩展 | VS Code 里搜扩展 **Go**（`golang.go`），装完执行一次 `Go: Install/Update Tools` |
| 格式化 / 检查 | `gofmt -w .`（保存时自动跑更省事）、`go vet ./...` |
| 依赖整理 | `go mod tidy`（第一次 `go test` 报 go.sum 相关错误时用） |

## 六、只有 1 小时的时候怎么选

```text
今天时间紧（<1h）        → 只跑 syntax/ 当天的示例 + 刷 1 道题，笔记写「卡点」一行
今天有 3h（标准情况）    → Tour 一块 + syntax 重敲 + 2 道题 + 题解
今天有 6h（周末/假期）   → 上午语法/标准库 + 下午 4 道题 + 补欠账 + 复盘
状态差                    → 切保底档：只保证「跑一遍昨天的代码 + 1 道题 + 一次提交」
```

**一条纪律**：资料是拿来「解决当下这个语法点」的，不是拿来「刷完」的。
W1 结束时你手上该有一个能跑的 Go 环境、20 道题的题解、一个公开仓库——**这三样比多看 10 小时视频值钱得多。**
