# go-dsa-lab 编写约定（内部规范）

> 这个文件是给「我和 AI 助手」看的写作规范，保证仓库里 40+ 个文件的风格一致。
> 对应 [W1-启动清单-Go主线.md](../W1-启动清单-Go主线.md)。

## 模块信息

- module：`github.com/yeziyesuan/go-dsa-lab`（换用户名时改两处：`go mod edit -module github.com/<你的用户名>/go-dsa-lab`，再把 `syntax/10_package/main.go` 里的 import 一起改掉）
- Go 版本：`go 1.22`（`for range` 每轮新变量的语义从 1.22 开始）
- 不引入任何第三方依赖，只用标准库（`go.mod` 里不允许出现 require）

## 代码规范

1. **注释用中文**，导出函数必须有 doc comment，以函数名开头（`golint` 风格）。
2. 每个题解文件的顶部注释写清四件事：**题目、思路、复杂度、卡点**。
3. 测试一律**表驱动 + `t.Run` 子测试**，用例包含题目示例 + 边界（空输入 / 单元素 / 全相同 / 负数）。
4. 不写 `panic`（除非演示 `panic/recover` 本身），不写 `init()`。
5. 命名用 Go 习惯：缩写全大写（`ID`、`URL`、`BFS`），不要下划线命名。
6. 变量名短：`i` `j` `n` `m` `l` `r` `lo` `hi` `ok` `err`；不要 `theIndex`。
7. 错误处理显式写 `if err != nil { return ..., err }`，不要用 `_` 忽略（示例中必须演示正确写法）。
8. 文件内不再分节，函数顺序紧跟其依赖（被调用的自己写的辅助函数放下面，标准库调用无所谓）。

## 事实约束

- 题号以 [W1-启动清单-Go主线.md](../W1-启动清单-Go主线.md) 第四节为准。
