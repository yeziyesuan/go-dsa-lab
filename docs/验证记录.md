## 三、第一次真编译时抓到的问题（留档，别删）

这批资料初稿是**在没有 Go 的机器上写出来**的，人工复查时两位审查者都判定「0 编译错误」。
拿到编译器后，第一次 `go vet ./...` 直接报出 **6 个语法文件编译不过**，`go test` 又报出 **5 处测试期望值写错**。

| 文件 | 真实错误 | 修法 |
|---|---|---|
| `syntax/01_types/main.go` | `cannot convert float64(3)/2 (constant 1.5) to type int`；`int(2.9)`、`int(-2.9)` 同样非法 | **常量**截断在编译期就不允许；改成先用变量接住再转，并把「常量 vs 变量」的区别写进注释 |
| `syntax/03_slice/main.go` | `no new variables on left side of :=`（`s2` 重名） | 重命名，保留两处演示 |
| `syntax/05_func/main.go` | `multiple-value namedQuotient(7, 2) in single-value context` | 用 `q, err := ...` 接住多返回值 |
| `syntax/06_pointer/main.go` | `append(s, 999) (value of type []int) is not used` | 裸 `append` 是「拿了返回值又丢掉」，改成显式接住/丢弃并说明原因 |
| `syntax/07_struct_method/main.go` | `undefined: Line`、`l.distSq undefined` | 补上缺失的类型/方法定义 |
| `syntax/09_error/main.go` | `multiple-value safeDiv(10, 2) in single-value context` | 同上，接住 `(result, err)` |
| `problems/p001_two_sum_test.go` | 用例 `[0,0,0], target 0` 期望「无解」，但正确答案就是 `[0,1]` | 拆成「全是零 → `[0,1]`」和「只有一个零 → 无解」两个用例 |
| `problems/p026_remove_duplicates_test.go` | `nums[:0]`（nil 切片）与 `[]int{}` 用 `reflect.DeepEqual` 判不等 | 改成按长度 + 逐元素比较 |
| `problems/p042_trap_test.go` | 两个用例期望值写错：`[0,1,2,1,0,1,2,1,0]` 应为 **4**（写了 3）；`[6,4,2,0,3,2,0,3,1,5]` 应为 **25**（写了 27） | 按 `min(leftMax,rightMax)-h[i]` 逐个位置重算后改正（同文件的「朴素解对拍」测试也印证了这两个数） |
| `problems/p053_max_subarray_test.go` | `[-2,1,-3,4,-1,2,1,-5,4,100]` 期望 101，实际最大子数组和是 **105** | 改为 105 |

**结论（也是 W1 最该记住的一件事）**：
> 人工读代码看不出编译错误，就像看懂语法不等于会写代码。
> 每题写完必须跑一次 `go test`，每个语法点必须 `go run` 一次——**这个仓库里所有注释说的"应该能跑"，都是被编译器验证过的。**
