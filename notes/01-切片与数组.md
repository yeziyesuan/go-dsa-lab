# 切片与数组：共享底层数组是最容易咬人的坑

- 类型：语法 · Go 基础
- 一句话定位：数组是"值"，切片是"指向数组的一张门票"，多张门票可能指向同一块地。
- 配套示例：`syntax/03_slice`（`go run ./syntax/03_slice`）

## 1. 数组是值类型，切片是描述符

数组长度是类型的一部分，`[3]int` 和 `[4]int` 不能互相赋值。**数组赋值即整块拷贝**，
传进函数改的是副本——和 Java 数组的引用语义正好相反（见第 7 节代码第 1 组）。
切片只有三个字段：指向底层数组的指针、长度 `len`、容量 `cap`。`len` 是能通过 `s[i]`
读到的下界；`cap` 是从起点到底层数组末尾还剩多少格，**决定 `append` 能不能"就地写"**——
能就地写，就意味着在改别人看得见的数组。

## 2. append 的扩容（实现细节，别背太死）

只有 `len == cap` 时 `append` 才分配新数组。当前实现里倍率大致是：小于 1024 按 2 倍增长，
超过 1024 按约 1.25 倍增长，并向内存分配器的规格就近取整，所以 `cap` 会从 1、2、4 跳。
**这是实现细节不是语言规范**，断言"append 后 cap 恰好是几"的代码是脆的；
需要精确容量就自己 `make([]T, 0, n)`。

## 3. 共享底层数组陷阱（重点）

```go
s1 := []int{1, 2, 3} // len=3 cap=3
s2 := s1[:2]         // len=2 cap=3，和 s1 指向同一个数组
s2 = append(s2, 9)   // s2 还剩 1 格空闲 → 直接写在原数组下标 2
```

```
底层数组:  [ 1 ][ 2 ][ 3 ]     ← 分配时的 3 格
             ↑
s1 (len=3, cap=3)、s2 (len=2, cap=3)：起点相同，cap 都到数组末尾
append(s2, 9) 覆盖下标 2 → 数组变成 [1][2][9]
```

结果 `s1` 变成 `[1 2 9]`：第三个元素被一个"什么都不知道"的 `append` 覆盖了，
没有任何编译期或运行期报错。反过来 `s2 := s1[1:3]` 的 `len == cap == 2`，
`append` 必须新开数组，`s1` 就安全。**会不会串味完全取决于 cap 有没有余量**。

## 4. 三种修复手段

`make([]int, len(src))` 后 `copy` 最明确；`append([]int{}, src...)` 一步到位；
`s1[0:2:2]` 这种三索引切片不拷贝，但把 `cap` 卡死在 `len` 上，让后续 `append`
别无选择只能新分配，适合"我要一个前缀视图，但绝不允许它改写原数据"的场景。

## 5. nil 切片 vs 空切片

`var a []int` 与 `b := []int{}` 的 `len`/`cap`/`range`/`append` 行为完全一样，
区别只在 `a == nil` 为 true，以及 `json.Marshal` 分别得到 `null` 和 `[]`。
给前端返回列表时建议统一用 `[]Item{}`。

## 6. 遍历时删除元素

正序删除会跳元素：删掉下标 `i` 后原本的 `i+1` 前移到 `i`，而下一轮 `i` 已经自增，
所以必须倒序 `for i := len(s) - 1; i >= 0; i--` 或改成"过滤到新切片"。

## 7. 可运行的复现代码

整段粘进 `main.go`（含 import）后 `go run .`：

```go
package main

import (
	"encoding/json"
	"fmt"
)

func main() {
	a := [3]int{1, 2, 3}
	b := a
	b[0] = 99
	fmt.Println("数组拷贝:", a, b) // [1 2 3] [99 2 3]

	s1 := []int{1, 2, 3}
	s2 := append(s1[:2], 9)
	fmt.Println("污染 s1:", s1, "s2:", s2) // [1 2 9] [1 2 9]

	s3 := []int{1, 2, 3}
	s4 := append(s3[1:3], 9) // len==cap → 新分配
	fmt.Println("无污染 s3:", s3, "s4:", s4) // [1 2 3] [2 3 9]

	s5 := []int{1, 2, 3}
	s6 := append(s5[0:2:2], 9) // 三索引锁死 cap
	fmt.Println("三索引 s5:", s5, "s6:", s6) // [1 2 3] [1 2 9]

	var nilS []int
	j1, _ := json.Marshal(nilS)
	j2, _ := json.Marshal([]int{})
	fmt.Printf("nil -> %s, empty -> %s\n", j1, j2) // null, []

	fwd := []int{1, 2, 2, 3}
	for i := range fwd { // range 轮数开始时已定，不会越界
		if fwd[i] == 2 {
			fwd = append(fwd[:i], fwd[i+1:]...)
		}
	}
	bwd := []int{1, 2, 2, 3}
	for i := len(bwd) - 1; i >= 0; i-- {
		if bwd[i] == 2 {
			bwd = append(bwd[:i], bwd[i+1:]...)
		}
	}
	fmt.Println("正序:", fwd, "倒序:", bwd) // [1 2 3] [1 3]
}
```

## 一句话结论

数组赋值拷整块，切片赋值只拷 ptr/len/cap；**只要 `cap` 还有余量，`append` 就会就地改到
共享的底层数组**，要切断这层关系就用 `make+copy`、`append([]int{}, s...)` 或 `s[a:b:b]`。
