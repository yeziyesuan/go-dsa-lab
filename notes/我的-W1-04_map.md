## 二、可以引用的实证（我自己跑出来的，直接拿去组织语言）

| 我做的实验 | 我看到的结果 |
|---|---|
| `var nilMap map[string]int`，然后**读 / `len` / `range` / `delete`** | 全部安全，不 panic |
| 同样的 nilMap，再写 `nilMap["x"] = 1` | `panic: assignment to entry in nil map` |
| `centers["origin"].X = 9`（value 是 struct） | 编译错误：`cannot assign to struct field centers["origin"].X in map` |
| `graph["a"] = append(graph["a"], 3)` | **必须整体写回**，否则 append 的结果就丢了 |
| 同一个 map `range` 跑 3 轮 | 每轮顺序都不一样（Go 故意随机化，不是 bug） |
| 想固定顺序 | 取 key → `sort.Strings` → 按 key 顺序取值 |
| 查一个不存在的 key | 单值写法拿到**零值 `0`**；`v, ok := m[k]` 才分得清"不存在"和"本来就是 0" |
| `delete` 一个不存在的 key | 不报错、不 panic |
